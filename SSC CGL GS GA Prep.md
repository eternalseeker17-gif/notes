Final structure — two parallel daily blocks, 15 days each, starting 23 Sep 2026

Block 1 = first-time subjects. Block 2 = revision (subjects already studied, then a 2nd-reading shadow of Block 1's early subjects, then both converge on Phy/Chem/Bio/Static GK). Both blocks run the same calendar day.

Block 1 order (15 days, 23 Sep–7 Oct): Geography (Day1-2, 16 tests: 11 Basic + 5 important Advanced) → Modern History (Day3-4, 14 Basic) → Economy (Day5, 4 Basic + Advanced 1-4) → Physics round1 (Day6, 3 Basic) → Chemistry round1 (Day7, Basic 1,4,5 + Advanced1) → Biology round1 (Day8-9, 6 Basic + Advanced 4-7) → Static GK (Day10-12, Dances+Festivals+Music+Books&Authors+Sports Basic+Advanced, 37 tests) → Physics Advanced add-on (Day13, 2 tests) → Biology Advanced add-on (Day14-15, Botany/Animal Kingdom/Zoology/Misc).

Block 2 order (15 days): Polity revision (Day1-3, no new tests, already done) → Ancient History revision + Medieval History first attempt combined (Day4-6, Medieval = 10 tests never attempted) → Geography 2nd reading (Day7-8) → Modern History 2nd reading (Day9-10) → Economy 2nd reading (Day11-12) → Chemistry new/held-back (Day13, 6 tests) → Static GK new/held-back, if time allows (Day14-15, 22 tests).

Per-subject held-back/revision splits (all user-specified, not diagnosis-driven):

Geography: Advanced held back = World Geography (all 4) + Indian Geography Transport/Economic-Human-Geography/Misc (3) — revision round, if time allows.
Economy: Advanced 5-11 (Money & Banking x2, National Income Accounting, Banking & Financial Awareness, Misc x3) held to revision round.
Chemistry: Basic 2,3,6 + Advanced 2-4 held to revision round (Block 2 Day13).
Biology: Advanced 1,2,3,8 (Botany, Animal Kingdom, Zoology, Misc) held — but placed as a Block 1 add-on (Day14-15), not Block 2.
Static GK: only Dances/Festivals/Music/Books&Authors/Sports (Basic+Advanced, 37 tests) go in Block 1 round 1; everything else (Architecture, Days & Events, Awards, Famous People/Places, Govt Policies, Sci-Tech — 22 tests) held to Block 2, if time allows.
Ancient History: Basic (6 tests) already attempted; Advanced (3 tests, 01/02/03) not yet attempted, timing flexible within Block 2 Day4-6.
Medieval History: notes can't start until N attempts the 10 tests, which happens during Block 2 Day4-6 itself — notes inherently trail this slot.

Deliverable: GS_GA_Final_Calendar.docx — daily combined checklist (both blocks under each day heading, exact test names), delivered to N. Supersedes GS_GA_Practice_Sequence.docx.

Revision-notes pipeline

Deliverable per subject: a unified keyword-style revision PDF merging two primary source books — Lucent GK Book (2026 English edition) and Parmar SSC "Fatman" (2nd Edition 2026) — both in N's Google Drive folder (https://drive.google.com/drive/folders/1zMNdymC0GMEl4RyAsgO4YPak6BHsWkMR). Same visual style as the original 14-topic Polity revision PDFs (claude/revision/style.css, aggressive keyword style, ★ = directly tested, mistake strips, HOOK-labelled mnemonics).

Third source changed 26 Sep 2026: PYQ book replaces Testbook attempts, going forward. N decided (see ssc-cgl-2026-prep) to focus PYQ practice on actual past SSC papers (CGL/CPO/Selection Post/CHSL/Stenographer) rather than Testbook's mock-test bank. This has real knock-on effects: (a) no personal attempt data anymore (no correct/incorrect, no "MY MISTAKE" boxes, no national-average/time-vs-avg stats — a book has no per-user telemetry), so ★-marking shifts to "this fact/question appeared in a real past paper" with an exact exam+date+shift citation instead of "N personally got this wrong"; (b) PYQ coverage spans multiple exam types, broader than Testbook's CGL-specific mock bank; (c) Ancient History and Polity were already built using Testbook-attempt data under the old approach — whether to leave them as-is or rebuild their tested-content layer against the PYQ book is still undecided with N.

PYQ book identified and filed 26 Sep 2026: "SSC General Awareness Smart Book — 3000+ Chapterwise PYQs" (Eduquity Pattern Decoder / Aditya Ranjan Sir), 366 pages, native digital PDF with selectable text (no OCR needed, unlike Parmar/Lucent) — big process win. Chapter structure maps almost 1:1 onto the existing claude/<subject>-raw/ folders. Full index + page-offset math saved to claude/pyq-book/pyq_index.md. The whole book (~31MB) is too large for project storage (blows the 2M-token project cap even split by subject as PDFs), so it was split into 6 subject-aligned PDFs and delivered to N via chat on 26 Sep — she should also drop the original (or the splits) into the same Drive folder as Lucent/Parmar for durable access, and attach the matching split into each subject-conversation when that subject is ready to move from raw-extraction to build.

Big scheduling implication, not yet fully absorbed into the calendar above: since the PYQ book is a static compilation (not gated on N attempting anything), the old "wait for this subject's tests to finish before building" constraint no longer applies to any subject sourced from it. Every subject that already has raw-extraction done (Economy, Physics, Chemistry, Static GK, Modern History, Medieval History — check each claude/<subject>-topic-build-notes.md for actual completion state) can move straight to build now, in any order, without waiting on the calendar's test-completion gates. Geography's build can also start once its raw-extraction is done, regardless of whether N has actually sat the Testbook Geography tests. The per-subject "held-back to revision round" splits above were designed around Testbook's round-1/round-2 test split and may no longer be the right sequencing now that tested-content doesn't depend on attempt order — worth revisiting with N rather than assumed.

Process decision: skip Polity's original 4-stage pipeline (detailed notes → merge 14 docs → dedup → keyword PDF) — the merge/dedup stage existed only to fix cross-topic repeats across 14 separately-built Polity docs, which doesn't apply when each GS/GA subject gets one PDF built directly. Adapted leaner process: raw-extraction ground truth → build keyword PDF directly (batched sub-topic by sub-topic) → factcheck/coverage sweep against the final PDF, with inline cross-reference boxes substituting for a dedup pass. Build order within a subject: sub-topics with both test + book coverage first, book-only sub-topics last.
